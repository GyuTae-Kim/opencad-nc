# OpenCAD NC 뷰어 · 해석기

NC 프로그램(G-code·Heidenhain 평문·woodWOP MPR·WangShi PGI·KDT XML)을 브라우저 안에서 읽어 3D 공구 경로로 보여 주는 뷰어 앱과, 그 해석기 라이브러리입니다.
해석기는 DOM·WebGL에 기대지 않아 웹 워커에서 돌고, 결과 장면(`Scene3d`)은 [opencad-viewer3d](https://github.com/GyuTae-Kim/opencad-viewer3d)로 그립니다.
다른 NC 해석 라이브러리를 쓰지 않고 새로 작성했습니다. G-code·Heidenhain 평문·woodWOP MPR은 공개 자료를 보고 작성했습니다.
WangShi PGI·KDT XML은 공개 형식 설명서가 없어, 비공개 리더의 형식 설명과 실제 출력 파일을 보고 맞췄습니다. 그 리더의 코드는 옮기지 않았습니다.

- 뷰어(배포 예정): https://gyutae-kim.github.io/opencad-nc/
- 함께 쓰는 저장소: [opencad-viewer3d](https://github.com/GyuTae-Kim/opencad-viewer3d)(3D 뷰어 코어) ·
  [opencad-step](https://github.com/GyuTae-Kim/opencad-step) · [opencad-skp](https://github.com/GyuTae-Kim/opencad-skp) · [OpenCAD 도구 모음](https://gyutae-kim.github.io/opencad)

## 할 수 있는 것

- G-code(ISO·Fanuc·Haas·Siemens·LinuxCNC·GRBL·Mach3 방언 자동 판별): 직선·호·나선, 평면·단위·좌표계, 고정 사이클, 부프로그램, 변수와 IF/WHILE
  - 이동은 800만 개까지 읽습니다(`maxMoves`). 파일 값이 한 줄의 반복 수를 정하는 자리(고정 사이클 반복 L·K, 볼트 구멍 패턴, 원형 포켓 반복, NURBS 조각, 선반 사이클, HOLES1·HOLES2,
    Heidenhain 패턴·밀링 사이클)는 돌 때마다 한도를 봐서, 아주 큰 반복 수나 아주 작은 간격 한 줄도 한도에서 멈추고 그 줄에 "이동이 …개를 넘어 나머지는 읽지 않음"을 한 번 남깁니다.
    한도는 이동이 쌓이는 자리(`MoveBuilder.push`)에서 지키므로 한 이동이 여러 이동이 되는 모서리 다듬기·회전축 감기·도그레그·곡선 조각도 넘지 못합니다. 여러 조각이면 남은 자리까지 쌓고, 뒤 이동을 읽기 전에 멈춘 모서리는 그대로 끝납니다. 쌓인 경로는 전체 경로의 앞부분이고, 바닥에 닿지 못한 구멍은 구멍 표에 넣지 않습니다(복귀만 잘린 구멍은 남습니다).
    LinuxCNC G71·G72는 구간이 200만 개를 넘으면 메모리를 지키려고 뒤 층을 보지 않고 그 줄에 "구간이 …개를 넘어 나머지는 읽지 않음"을 남기고 멈춥니다. 이때는 뒤 층의 열린 구간이 빠져 포켓이 앞당겨지므로 전체 경로의 앞부분이 아닙니다.
    줄을 되풀이하는 반복(M98 L·REPEAT·CALL LBL REP)은 실행 블록 한도가 막습니다.
    사이클 하나 안에는 아주 작은 절입·간격이 끝나지 않게 막는 횟수 상한이 따로 있습니다. 쪼기(G73·G83·Siemens CYCLE83·Heidenhain 200·203·205·옛 사이클 1은 구멍마다,
    선반 G74·G75는 자리마다 1만 번), 층(Fanuc 선반 G71·G72 9,999층, LinuxCNC G71·G72 1만 층, Heidenhain 밀링 사이클 9,999층 + 바닥 층), G12·G13 원형 포켓의 원 1,000개, G76 절입 499번입니다.
    상한에 닿으면 거기까지 그린 그대로 두고(쪼기는 그 깊이에서 물러나고, 층은 남은 층을 건너뛰어 다듬질 윤곽이나 바닥 층으로, 원은 마무리 원으로, 나사는 남은 절입을 건너뜀)
    그 줄에 사이클 이름과 함께 "쪼기가 10000번을 넘어 바닥에 닿기 전에 멈춤"처럼 알립니다. 이동 한도가 먼저 막으면 이동 한도 경고만 남습니다.
    상한에 닿지 않는 프로그램의 해석 결과는 예전과 같습니다
  - 판별은 괄호 주석을 떼고 봅니다. 낱말에 붙은 주석(N1(…)·T1M6(…)·G0X0(…))과 겹친 주석 "(… (SPOT))"도 주석이고,
    Siemens 함수 인수(CYCLE81(…)·=AC(…)·SIN(…))와 식 괄호(= 뒤)는 남깁니다. Siemens 표지가 하나뿐이면 Fanuc·LinuxCNC의 뚜렷한 표지
    (O 번호 줄·# 변수·M98/G65 P·o-코드 부프로그램)가 없을 때만 Siemens로 읽습니다(표지가 둘 넘거나 %_N_ 머리면 Siemens)
  - Siemens Sinumerik(840D sl·828D 꼴, `src/siemens.ts` — %_N_…_MPF 머리·MCALL·CYCLE·T="…"·CR=·AC/IC·GOTOF·DEF·SUPA 등으로 판별):
    `;` 주석, 주소 = 식(X=R1*2), 축별 AC(…)/IC(…), CR=·I=AC(…)·AR=·CIP(I1/J1/K1)·TURN=, 극좌표 G110~G112 + AP·RP,
    공구 T="이름"·D·M6, R 매개변수·DEF 변수·PROC 매개변수와 식(SIN…ATAN2·POT·TRUNC·ROUND·MIN·MAX·DIV·MOD·비교·AND/OR/NOT),
    IF … GOTOF/GOTOB/GOTO/GOTOC·IF/ELSE/ENDIF·WHILE·FOR·REPEAT/UNTIL·LOOP·REPEAT 표지 P=, 부프로그램 L123 P3·이름·이름(인수)·
    CALL "이름"·MCALL 이름(같은 글의 %_N_이름_SPF·PROC나 함께 연 파일), RET·M17, 드릴 사이클 CYCLE81~89·840(MCALL 모달,
    CYCLE83 FDEP·FDPR·DAM·VARI)·HOLES1·HOLES2, 프레임 TRANS·ATRANS·ROT·AROT·SCALE·ASCALE·MIRROR·AMIRROR·G58·G59(절대 지령은 프레임을 바꿈),
    G54~G57·G505~G599, SUPA·G53·G153·G74·G75(기계 좌표 쪽 이동 규칙), G70/G71/G700/G710, G4 F(초)·S(회전),
    CT(앞 요소에 접하는 원호 — 모달, G0~G3·CIP가 끔), 모서리 다듬기 RND=(둥글리기 반지름)·RNDM=(모달, 0이면 끔 — 직선·원호 블록 모두)·
    CHF=(모따기 선 길이)·CHR=(모서리에서 자르는 길이) — Siemens 설명서대로 작업 평면 안의 직선·원호 어느 조합이든.
    둥글리기는 두 요소에 접하는 호(두 요소를 반지름만큼 옮긴 선·원의 교점 가운데 모서리에 가까운 것이 중심), 원호 위 모따기 점은 모서리에서
    현 길이로 잰 거리이고 CHF는 모따기 선 길이가 값과 같아지게 두 거리를 맞춥니다. 원호의 중심은 그대로 두고 끝·시작만 접점으로 옮깁니다.
    나선처럼 작업 평면 밖으로 움직이는 모서리, 요소보다 큰 값은 그대로 두고 경고합니다.
    포켓 사이클 POCKET3(사각)·POCKET4(원)는 SINUMERIK 840D sl 사이클 프로그래밍 설명서(3.9·3.10절)의 매개변수 차례·뜻대로 그립니다 —
    후퇴 면에서 포켓 중심 위로 → 기준면 + 안전 거리 → 진입(_VARI 십의 자리: 수직 G0·수직 G1·나선 _RAD1·_DP1) → _MID 이하 같은 절입의 층마다
    중심에서 바깥으로 고리(옆 간격 _MIDA, 없으면 공구 지름 × 0.8)로 가장자리 여유 _FAL·바닥 여유 _FALD까지 → 후퇴 면.
    정삭(_VARI X2)은 가장자리 윤곽 한 바퀴 뒤 바닥 한 번이고, 기준점(중심·모서리)·긴 축 각 _STA·사이클 설정 _ZSD[1]·[2]·[9](프로그램이 대입한 것만),
    가공 방향 _CDIR(0 하향·1 상향 — 주축 방향으로 셈, 2 G2·3 G3), 평면 G17~G19·프레임을 따릅니다. 블랭크 치수(_AP·_AD)·POCKET4 나선 가공(_VARI 1xxx)·
    POCKET3 왕복 진입(_VARI 3X)은 경고하고 온 포켓·층마다 평면 가공·수직 진입으로 그리고, 깊이·크기가 없거나 공구가 포켓보다 크거나 _VARI가 맞지 않으면 그리지 않습니다.
    한 줄의 사이클이 만드는 층·고리·나선 바퀴마다 이동 한도(`maxMoves`)를 봐서, 아주 작은 _MID·_MIDA·_DP1이나 아주 큰 깊이·크기도
    한도에서 멈추고 "이동이 …개를 넘어 나머지는 읽지 않음"으로 경고합니다(블록 사이에서만 보면 한 줄이 한도를 크게 넘을 수 있음).
    사각 포켓 POCKET1·원 포켓 POCKET2도 같은 설명서(3.7·3.8절, 매개변수 FFD·FFP1·MID·CDIR·FAL·VARI·MIDF·FFP2·SSF는 두 절이 가리키는 3.5절 SLOT1 설명)대로 그립니다 —
    후퇴 면에서 포켓 중심 위로 → 기준면 + 안전 거리 → MID 이하 같은 절입의 층마다 중심에서 G1(FFD)로 진입해 가장자리 여유 FAL까지 중심에서 바깥으로 고리(FFP1) →
    정삭은 MIDF 이하 층마다(0이면 바닥에서 한 번) 중심에서 진입해 윤곽 한 바퀴(FFP2, 없으면 FFP1) → 포켓 중심 위 후퇴 면입니다.
    VARI는 0 온 가공(황삭 뒤 정삭)·1 황삭·2 정삭이고, 가공 방향 CDIR은 2(G2)·3(G3), 중심 CPA·CPO·긴 축 각 STA1·모서리 CRAD·_ZSD[1]·평면·프레임을 따릅니다.
    너무 큰 FAL은 가능한 만큼으로 줄이고, 정삭 회전수 SSF는 반영하지 않고 경고하며, 깊이·크기가 없거나 공구가 포켓보다 크거나 VARI가 맞지 않으면 그리지 않습니다.
    사이클 깊이 DP·DPR(드릴 사이클·LONGHOLE·SLOT1·SLOT2·POCKET1·POCKET2)은 설명서(2.1.3절)대로 상대 깊이 DPR을 기준면에서 후퇴 면 반대쪽으로 재고,
    둘 다 있으면 DPR을 쓰며 DP와 다르면 경고합니다(빠진 매개변수는 0이라 DPR = 0은 적지 않은 것과 같음).
    CYCLE83의 첫 드릴 깊이도 같은 규칙입니다. FDPR은 사이클에서 DPR과 같은 구실을 하고(2.1.5절), CYCLE83은 둘 다 받으면 상대 값을 따른다고 알리므로(5.3절)
    FDEP와 FDPR이 둘 다 있으면 FDPR로 그리고 FDEP와 다르면 경고합니다(FDPR = 0은 적지 않은 것과 같아 FDEP).
    사이클은 후퇴 면이 기준면 앞(최종 깊이에서 더 멂)이라고 봅니다(2.1.3절 44쪽). 그래서 후퇴 면과 기준면이 같은데 상대 깊이 DPR을 주었거나
    후퇴 면이 기준면 뒤(최종 깊이에 더 가까움)이면 설명서대로 알람 61101이라 그 사이클을 그리지 않고 그 줄에 경고합니다. 드릴 사이클·HOLES1·HOLES2로 부른 것,
    LONGHOLE·SLOT1·SLOT2·POCKET1~POCKET4가 모두 같습니다(2.1.1절 — 기하 매개변수는 드릴·패턴·밀링 사이클에 같음, 다른 사이클의 RTP·RFP 설명도 CYCLE81을 가리킴).
    후퇴 면과 기준면이 같아도 절대 깊이 DP(또는 DPR = 0)면 그대로 그립니다
    원 위 긴 구멍 LONGHOLE·원 위 홈 SLOT1·원주 홈 SLOT2도 같은 설명서(3.4~3.6절)의 매개변수 차례·뜻대로 그립니다. 자리는 원 중심 CPA·CPO와 반지름 RAD,
    시작 각 STA1·간격 INDA(0이면 360 / NUM)입니다. LONGHOLE·SLOT1은 긴 축이 반지름 방향이고 안쪽 끝이 원에 닿아 바깥으로 LENG만큼이며(설명서 그림),
    너비는 LONGHOLE이 공구 지름, SLOT1이 WID입니다. SLOT2는 원을 따라 STA1에서 반시계로 AFSL만큼(양 끝 반원 중심 사이 각), 너비 WID이고 AFSL이 360 이상이면 고리 홈입니다.
    깊이는 DPR(둘 다 있으면 DPR)이나 DP까지 MID 이하의 같은 절입으로 가장 적은 층이고, _ZSD[1]을 따릅니다.
    LONGHOLE은 설명서 순서대로 후퇴 면에서 가까운 끝 위로 → 기준면 + 안전 거리 → 끝마다 다음 깊이로 G1(FFD) 진입하며 FFP1로 왕복 → 후퇴 면 → 다음 구멍의 가까운 끝입니다.
    SLOT1·SLOT2는 층마다 홈 둘레 고리 하나로 마무리 여유 FAL까지 깎고(공구 지름이 너비의 반보다 작으면 가운데가 남는다는 설명에 맞춤), 정삭(VARI 일의 자리 0·2)은
    MIDF 이하 층마다(0이면 바닥 한 번) 홈 윤곽을 FFP2로 한 바퀴 돕니다. 너비 − 2 × FAL이 공구 지름이면 LONGHOLE처럼 양 끝에서 번갈아 진입하며 왕복하고,
    SLOT1의 바닥 여유 _FALD, 진입 방법(VARI 십의 자리 — 수직 G0·수직 G1·홈 가운데 축 위 왕복 진입, 각 _STA2 이하), 가공 방향 CDIR(0 하향·1 상향·2 G2·3 G3),
    SLOT2의 홈 사이 옮김(후퇴 면에서 G0 직선이나 원을 따라 _FFCP)과 가장자리만 정삭(VARI 3)을 따릅니다. 정삭 회전수 SSF는 반영하지 않고 경고하며,
    깊이·개수·크기가 없거나 맞지 않음, 공구가 홈보다 큼(알람 61105), 홈끼리 겹침(알람 61104), VARI가 맞지 않음(알람 61102)이면 그리지 않습니다.
    평면 밀링 CYCLE71도 같은 설명서(3.11절 156~162쪽)대로 그립니다 — (_PA, _PO)에서 _STA만큼 돈 _LENG × _WID 면을, 지금 높이에서 진입 자리 →
    기준면 + 안전 거리 → 면 밖에서 G0으로 가공 높이 → 거친 깎기는 _DP + _FALD까지 _MID 이하 같은 절입의 층마다(_ZSD[1]을 따름), 다듬질은 _DP에서 한 번 → 후퇴 면입니다.
    _VARI 십의 자리 1·3은 긴 축과, 2·4는 수직 축과 나란히 깎고, 1·2는 한 방향(길 끝에서 그 층 + 안전 거리, 다듬질은 _DP + _FALD + 안전 거리로 들어 올려 급속으로
    다음 길 시작), 3·4는 오가며 깎습니다. 첫 길은 가장자리에서 꼭 _MIDA만큼 물리고(공구 중심 = _MIDA − 공구 반지름), 마지막 길의 공구 중심은 너비 + _FDP1 − 공구 반지름,
    사이는 _MIDA 이하 같은 간격입니다(_MIDA가 0이면 공구 지름의 80 %). _VARI가 맞지 않음(알람 61002)·알람 61101·깊이나 크기 없음은 그리지 않고 경고합니다.
    윤곽 밀링 CYCLE72도 같은 설명서(3.12절 163~170쪽)대로 그립니다 — CYCLE72(_KNAME, _RTP, _RFP, _SDIS, _DP, _MID, _FAL, _FALD, _FFP1, _FFD, _VARI, _RL, _AS1, _LP1,
    _FF3, _AS2, _LP2). 윤곽 _KNAME은 CYCLE95와 같이 찾고(부프로그램 이름·"표지1:표지2"·"이름:표지1:표지2"), 첫 블록이 윤곽 시작입니다.

    (G-code도 공작물 바닥까지 깎은 곳은 같음. 직사각형이 아닌 판의 외곽선 밖은 그대로 바닥 색).
  - 합성 프로그램 30만 이동을 끝까지 깎는 데 볼 엔드밀 3D 곡면은 약 2.5초(자동 553칸)·6.3초(1024칸), 평 엔드밀 포켓은 약 1.2초(1024칸) 걸렸습니다.
    판 2400 × 1200 MPR(구멍 620개·홈·포켓·윤곽, 이동 약 2천 개)은 1024칸에서 깎기와 그물 만들기를 합쳐 0.03초 안쪽입니다
    (`npm run sim:bench`, 이 저장소 개발 기기의 Node 한 스레드). 실제 판재 파일 1,759개 가운데 윗면 가공이 있는 722개(MPR·PGI·XML)도
    1024칸에서 예외 없이 끝까지 깎았고, 한 파일에 가운데값 약 6 ms, 90%가 16 ms 안쪽이었습니다.
    그 가운데 판을 뚫은 곳이 있는 66개도 그물을 만들 때 예외가 없었고, 바닥과 비운 윗면을 합친 넓이가 소재 넓이와 같았습니다.

## 뷰어 앱 쓰는 법

1. 파일을 창 어디에나 끌어다 놓거나 **열기**(Ctrl/⌘+O)를 누릅니다. **예제 열기**는 코드로 만든 합성 G-code를 엽니다.
   파일은 서버로 올리지 않고 이 기기 안에서 읽습니다(해석은 웹 워커).
   주 프로그램과 부프로그램 파일을 함께 고르거나 놓으면 한 작업으로 이어 읽습니다(띠 "파일 N개를 한 작업으로 읽었습니다 — 주 프로그램 …").
   다른 파일에 있을 프로그램을 찾지 못하면 띠 "다른 파일의 프로그램 …을(를) 찾지 못했습니다"의 **파일 더하기**로 그 파일을 골라 더합니다.
   작업의 줄 번호(코드 줄 번호 칸·해석 경고·상태·재생 띠)는 원래 파일의 줄로 보입니다("O1001.nc · 4번 줄" — 파일 사이 표지 줄은 번호를 비움).
   코드 찾기의 ":120"은 고른 줄이 있는 파일(없으면 주 프로그램)의 120번 줄로 갑니다.
2. 가운데 3D 보기: 왼쪽 끌기 회전, 가운데·오른쪽 끌기 이동, 휠 확대(터치는 한 손가락 회전·두 손가락 이동·핀치).
   터치는 10화소(코어 `TOUCH_DRAG_START_PX`)보다 덜 움직이고 떼면 누르기로 보고(6~9화소 떨려도 모형이 돌지 않음),
   누르기·측정 점은 선분에서 14화소(코어 `touchPickTolerance` 기본값) 안이면 고르며 끝점에서 14화소 안이면 끝점에 붙잡습니다(마우스는 6·10화소 그대로).
   보기 도구 막대에 전체 보기, 표준 뷰, 원근/평행, 그리기 모드(음영·음영+모서리·와이어프레임·X-ray), 격자, 뷰 큐브, 좌표축,
   **단면**(끔·X·Y·Z 축 고르기, 위치 슬라이더, 뒤집기 — 새 문서를 열면 꺼짐), 두 점 측정, PNG 저장, 패널 열고 닫기가 있습니다.
   G-code·Heidenhain의 두 점 측정은 끝점 말고도 G2/G3 원호의 **중심**(구멍 가운데처럼 빈 자리라도 커서가 오면)과 이동의 **가운데 점**에 붙습니다.
   원호의 가운데 점은 현의 가운데가 아니라 호 위의 점이고(나선은 높이도 반), 중심은 해석기가 읽은 값 그대로입니다.
   반경 보정 경로(공구 중심)에서는 보정한 조각의 가운데 점과 호 중심에 붙습니다.
   판재 파일(MPR·PGI·XML)은 윤곽(자유 형상 포켓 윤곽 포함)과 판 외곽선의 원호 중심, 지름을 아는 원형 포켓의 중심, 고른 윤곽 요소(직선·호)의 가운데 점에 붙습니다.
   측정 중에는 판·포켓·홈·구멍의 모서리선(이미 그려 둔 선)도 고르므로 판 외곽선, 포켓 둘레(둥근 사각 포켓의 모서리 — MPR Tasche의 RD도, 경로 포켓의 호, 원형 포켓 —
   옆면에서 판 것도), 구멍 테두리(위·아래 원 — 옆면 구멍도)의 호에서도 호의 가운데 점·중심에 붙습니다.
   스플라인(G5·G5.1·G5.2/G5.3)의 가운데 점은 나눈 조각 하나의 가운데가 아니라 곡선 전체의 길이 가운데(곡선 위)입니다.
   원호(나선, 반경 보정 경로의 호, 판재 윤곽·판 외곽선·포켓 둘레·구멍 테두리의 호 포함)와 스플라인은 짧은 직선 토막으로 그리므로 그 토막 위를 찍거나
   토막에 수직 발을 내리면 원래는 곡선에서 조금 안쪽에 찍혔습니다. 이제 찍힌 점을 정확한 곡선 위로 옮겨(3D 뷰어 코어 0.14.0 다듬기)
   거리·dx·dy·dz가 곡선 위 값입니다 — 예를 들어 원호 중심에서 원호 위 아무 점까지 잰 거리가 반지름 그대로이고, 원 밖 점에서 내린 수직 발은
   반지름 방향의 원 위 점입니다. 첫 점이 원호에서 멀어 토막마다 내린 발이 모두 토막 밖으로 떨어져도 곡선 위 진짜 발에 붙습니다.
   두 경로의 **교차점**도 원호·스플라인이 끼면 토막끼리 만나는 자리가 아니라 두 곡선이 실제로 만나는 점입니다(3D 뷰어 코어 0.15.0 다듬기 —
   직선과 원, 두 원은 식으로, 스플라인·나선이 끼면 두 매개변수 뉴턴으로 풂). 다른 평면의 두 원호처럼 토막끼리는 조금 비켜 지나가도
   곡선이 만나면 붙고, 높이가 달라 3D로 만나지 않는 두 경로에는 붙지 않습니다.
   판재 파일도 윤곽 경로·구멍 테두리·포켓 둘레·판 외곽선의 호가 다른 경로나 판·포켓·홈의 곧은 모서리선과 만나는 점은 원 위 정확한 교차점입니다
   (둥근 포켓의 곧은 변뿐 아니라 각진 포켓·홈 상자·직사각형 판의 모서리도).
   어느 형식이든 두 경로가 3D에서 만나는 **교차점**, 첫 점을 찍은 뒤 커서 둘레 경로로 내린 **수직 발**에도 붙고,
   붙을 점이 없으면 첫 점에서 **X·Y·Z축 방향**이나 커서가 지나간 경로 선분과 **나란한 방향**의 점을 잡습니다(3D 뷰어 코어의 추론 붙잡기).
   나란한 방향의 기준은 곧은 선분(직선 이송·급속·드릴, 보정 경로의 직선, 판재의 곧은 윤곽 요소와 판·포켓·홈의 곧은 모서리선)만이라,
   원호·스플라인·구멍 테두리를 나눈 짧은 현 위를 지나가도 앞서 지나간 곧은 선분이 기준으로 남습니다(3D 뷰어 코어 0.29.0).
   마우스를 올리면 표식 모양으로 종류를 보이고(끝점 네모·가운데 점 세모·중심 ⊕·교차점 ×·수직 발 ⊥, 축 방향은 첫 점에서 축 색 점선,
   나란한 방향은 자홍 점선과 ∥), 커서 옆 툴팁에 "끝점"·"X축 방향"·"나란한 방향"처럼 이름을 적습니다.
   코어가 그리는 거리 글상자는 툴팁 자리(커서 오른쪽 아래)를 비켜 그리고(3D 뷰어 코어 0.13.0), 글상자가 비킬 곳이 없을 때만
   툴팁이 커서 왼쪽이나 위로 비켜 섭니다. 오른쪽 위 뷰 큐브와 3D 보기 위에 뜬 띠(측정 띠·해석 판단 띠·재생 띠)도 비켜 그리므로
   두 점이 화면 구석이나 아래쪽에 있어도 거리가 가려지지 않습니다. 겹치지 않으면 자리는 그대로입니다.
   거리 글상자는 두 점의 표식(첫 점과 커서 아래 점)도 덮지 않게 비켜 그립니다(3D 뷰어 코어 0.31.0). 휴대폰은 글상자가 화면 폭의 절반을 넘어
   화면 안으로 당겨지므로, 첫 점이 두 점 가운데의 위쪽이면 글상자가 첫 점 표식을 덮었습니다. 표식을 덮지 않던 자리는 그대로입니다.
   그림 저장(PNG)에 담기는 거리 글상자도 두 표식을 덮지 않게 옮깁니다(3D 뷰어 코어 0.33.0 — 그림에는 십자선·툴팁이 없어 표식만 비킵니다).
   0.32.0까지는 그림의 글상자가 기본 자리라, 화면에서 비킨 글상자가 그림에서는 첫 점이나 둘째 점 표식을 덮곤 했습니다.
   거리 글상자의 이름표는 화면 언어로 그립니다("Distance"·"距離"·"距离"·"Abstand" — 수와 자릿수는 한국어 화면과 같음). 언어를 바꾸면 곧 다시 그리고,
   그림 저장(PNG)에 담기는 글상자도 같습니다.
   결과에는 "중심 → 가운데 점", "끝점 → X축 방향"처럼 두 점의 종류를 적습니다.
   **방향 잠금**(SketchUp 추론 잠금): 첫 점을 찍은 뒤 Shift를 누르고 있으면 지금 방향(축·나란함·수직)을 잠가 그 선 위에만 찍고, 다른 점을
   가리키면 그 점을 선으로 옮긴 자리(예: Z축을 잠그고 다른 경로 끝을 가리키면 그 높이)를 찍습니다. 첫 점이 경로 끝이고 그 경로를 따라
   다른 끝점·가운데 점·교차점을 가리킬 때도 그 경로 방향(축과 나란하면 그 축)으로 잠급니다 — 경로 몸통을 지나지 않고 끝점으로 바로 가도 됩니다
   (3D 뷰어 코어 0.12.0). 상태 줄은 커서 아래에 Shift로 잠글 방향이 있을 때만 "Shift로 X축 방향 잠그기"처럼 알리고, 없으면 "화살표로 방향 잠금"입니다.
   화살표 → X · ← Y · ↑ Z축, ↓ 지금 방향(없으면 첫 점 뒤 마지막으로 본 방향)으로 잠그고 같은 키로 풉니다(코드 목록·메뉴·탭에 초점이 있으면 그쪽 키).
   잠그면 굵은 안내선과 툴팁·상태 줄의 "X축 방향으로 잠금"으로 알리고, 잠근 선 위에 찍은 결과는 "끝점 → X축 방향 · 잠금"입니다.
   둘째 점을 찍거나 지우면 풀립니다.
   첫 점이 G2/G3 원호(나선 포함)의 시작이나 끝이고 커서가 그 원호 위(가운데 점·다른 끝 등)에 있으면 Shift·↓·잠금 단추는 그 끝에서의
   원호 **접선 방향**으로 잠급니다. 첫 점을 원호의 가운데 점이나 원호 위 다른 자리(원호를 나눈 현 위의 아무 점, 현의 끝)에 찍었어도
   커서가 그 원호 위에 있으면 그 점의 접선으로 잠급니다. 현 위에 찍은 점은 원호에서 조금 안쪽이라, 원호에서 가장 가까운 자리의 접선을
   그 점을 지나게 씁니다. 잠근 방향은 첫 점에서 원호를 따라 커서 쪽으로 나가는 쪽입니다(한 바퀴 원은 가까운 쪽).
   판재 파일(MPR·PGI·XML)의 윤곽 가공과 가공 없는 윤곽에 든 호, 판 외곽선·포켓 둘레·구멍 테두리의 호도 끝·가운데 점·호 위 다른 자리에서 같은 접선으로 잠급니다.
   보정 경로 보기를 켰을 때 반경 보정 경로(공구 중심 — G41/G42 원호를 공구 반지름만큼 옮긴 호, 바깥 모서리를 도는 호)의 호도 같습니다.
   스플라인(G5·G5.1·G5.2/G5.3)도 끝·가운데 점·곡선 위 아무 점에서 그 자리의 정확한 접선으로 잠급니다(조각 위에 찍은 점은 곡선 위 가장 가까운 자리).
   원호를 나눈 현 하나의 방향이 아니라 실제 접선이고(나선은 높이 기울기도, G18·G19 평면도 맞음),
   툴팁·상태 줄·결과에 "접선 방향"이라 적습니다. 커서 아래가 축·나란함·수직 발이면 그쪽이 먼저입니다.
   첫 점이 놓인 곡선은 3D 뷰어 코어 0.16.0이 찍은 점에 실어 주는 선분 식별자로 그 이동(보정 경로면 그 이동의 보정 조각)·윤곽에서 바로 찾으므로, 이동이 아주 많은 프로그램에서도
   첫 점을 찍을 때 모든 이동을 다시 훑지 않습니다(원호 20만 개에서 첫 점 한 번 약 31 ms → 0.04 ms). 곡선이 바뀌는 꼭짓점과 원호의 가운데 점·중심은
   식별자가 한쪽 이동만 가리키거나 없어서 예전처럼 좌표로 찾습니다.
   **끌어온 축**(SketchUp 추론 따라가기 — 3D 뷰어 코어 0.16.0): 끝점·가운데 점·중심·교차점 같은 점 위에 마우스를 0.5초쯤 멈추면 그 점을 기억하고
   (최근 셋까지, 작은 십자로 표시), 그 점을 지나는 X·Y·Z축 위에도 붙습니다(툴팁·결과 "끌어온 점에서 X축", 그 점에서 점선).
   첫 점을 찍은 뒤에는 첫 점의 축 위에서 기억한 점과 나란한 자리에도 붙는데, 이 점은 첫 점에서 그 축 방향이라 "X축 방향"으로 적고 Shift로 잠글 수 있습니다.
   두 점을 기억하면 한 점의 축과 다른 점의 다른 축이 3D로 만나는 점(툴팁·결과 "끌어온 Y축과 X축의 교차" — 첫 점을 찍기 전에도),
   끌어온 축이 경로 선분이나 판·포켓·구멍의 모서리선과 만나는 점("끌어온 점에서 X축 · 모서리 위")에도 붙습니다(3D 뷰어 코어 0.17.0).
   높이가 달라 3D로 만나지 않는 두 축에는 붙지 않습니다.
   **끌어온 점에서 모서리와 나란함·수직**(3D 뷰어 코어 0.28.0): 끌어온 점이 있으면, 커서가 앞서 지나간 곧은 선분(직선 이송·급속·드릴, 보정 경로의 직선,
   판재의 곧은 윤곽 요소와 판·포켓·홈의 곧은 모서리선)과 나란하게 그 점에서 그은 선, 그 선분에 수직으로 그은 선 위에도 붙습니다
   (툴팁·결과 "끌어온 점에서 모서리와 나란히"·"끌어온 점에서 모서리에 수직", 기준 선분은 자홍 점선). 원호·나선·스플라인과 보정 경로의 호,
   판재 윤곽 호·판 외곽선·포켓 둘레·구멍 테두리의 호를 나눈 짧은 현은 기준이 되지 않아, 곡선 위를 지나가도 앞서 지나간 곧은 선분이 기준으로 남습니다.
   CAM이 곡선을 짧은 직선 이송(G1)으로 풀어 쓴 구간, 회전축 감기로 나눈 이동, 좌표 변환 평면과 다른 평면의 원호·선반 윤곽 원호를 나눈 토막도
   이웃 토막 사이 꺾임으로 곡선 조각을 가려 기준에서 뺍니다(판정 규칙은 개발 절). 긴 직선과 모서리를 도는 짧은 직선은 그대로 기준입니다.
   기준이 X·Y·Z축과 나란한 판 모서리면 그 선은 끌어온 축과 같아 "끌어온 점에서 X축"으로 붙습니다. 첫 점을 지나는 선이 아니어서 Shift로 잠그지 않습니다.
   그 선이 다른 것과 만나는 점에도 붙습니다(3D 뷰어 코어 0.29.0): 첫 점의 X·Y·Z축("끌어온 점에서 모서리에 수직 · X축 위"), 첫 점에서 그은 나란한 방향
   ("… · 나란한 방향 위"), 다른 끌어온 점의 축("… · 끌어온 점 Y축 위"), 경로 선분·모서리선("… · 모서리 위"), 소재 면("… · 면 위")과 만나는 점입니다.
   원호·스플라인·구멍 테두리와 만나면 토막 위가 아니라 곡선 위의 실제 교차점, 구멍 벽·둥근 포켓 벽을 뚫으면 원기둥 위의 점입니다.
   그 선이 곡선을 나눈 짧은 현과는 만나지 않고 현과 곡선 사이만 지나는 자리에서도 곡선 위 교차점에 붙습니다(3D 뷰어 코어 0.31.0) —
   두 깊이로 깎은 원호의 평면을 비스듬히 뚫는 선(경사 진입과 나란한 선)이나 곡선에 거의 닿듯 지나는 선을 크게 당겨 볼 때입니다.
   판재에서는 그 선이 구멍 벽·둥근 포켓 벽·판 외곽선 둥근 모서리를 나눈 삼각형을 비켜 가며 벽 곡면만 뚫는 자리(벽에 거의 닿듯 지나는 선)에서도
   원기둥 위 교차점에 붙습니다(3D 뷰어 코어 0.32.0). 구멍 안에서 벽을 아주 가까이(거리 0.5~2) 당겨 봐도 그 선이 벽을 비켜 가거나 뚫는 두 교차에
   원기둥 위로 붙습니다(3D 뷰어 코어 0.34.0 — 세운 구멍과, 기둥 방향으로 긴 누운 구멍도). 그 선이 벽을 반지름의 0.2~2 % 안쪽으로 스칠 때
   그물을 뚫는 자리가 원기둥 밖으로 조금 비켜 잡혀도 그 선의 원기둥 위 교차에 붙습니다(57차).
   첫 점의 축과 만나는 점은 Shift로 그 축에, 첫 점의 나란한 방향과 만나는 점은 그 방향으로 잠글 수 있습니다.
   끌어온 점이 둘이면 두 점에서 같은 기준 선분으로 그은 나란한 선·수직인 선끼리 만나는 점(기운 사각형의 구석)에도 붙습니다(3D 뷰어 코어 0.30.0 —
   "끌어온 점에서 모서리에 수직 · 끌어온 점 나란한 선 위"·"끌어온 점에서 모서리와 나란히 · 끌어온 점 수직인 선 위"). 높이가 달라 3D로 만나지 않는 두 선에는
   붙지 않고, 첫 점을 지나는 선이 아니어서 Shift로 잠그지 않습니다. 기준이 X·Y축과 나란한 판 모서리면 두 선이 끌어온 축과 같아 예전처럼 "끌어온 X축과 Y축의 교차"입니다.
   휴대폰처럼 좁은 화면에서도 다른 언어로 옮긴 긴 툴팁 이름을 옮긴 글의 길이로 3D 보기 안에 두고, 보기보다 길면 두 줄로 바꿉니다.
   **축과 모서리·면이 만나는 점**(3D 뷰어 코어 0.18.0): 첫 점을 찍은 뒤 첫 점의 X·Y·Z축이 다른 경로나 판·포켓·구멍의 모서리선과 만나는 점("X축 · 모서리 위"),
   첫 점의 축이나 끌어온 축이 공작물(Heidenhain BLK FORM)·판·포켓·홈·구멍·깎기 시뮬레이션 소재의 면을 뚫는 점("X축 · 면 위"·"끌어온 점에서 X축 · 면 위")에도 붙습니다.
   첫 점에서 그 축 방향의 점이라 Shift로 그 축에 잠글 수 있습니다. 축이 원호(나선, 반경 보정 경로의 호, 판재 윤곽·판 외곽선·포켓 둘레·구멍 테두리의 호)나
   스플라인을 나눈 토막과 만나면 토막 위가 아니라 축과 곡선이 실제로 만나는 점에 붙고(끌어온 축도), 찍힌 점은 축에서 벗어나지 않습니다
   (예: 경로 끝에서 X축을 따라 원호까지 잰 dy·dz가 0, 원 위 반지름 그대로). 판재의 구멍 벽·원형 포켓 벽·둥근 사각 포켓 모서리·판 외곽선 둥근 모서리처럼
   원기둥 벽을 뚫는 점도 벽을 나눈 삼각형 위가 아니라 축과 원기둥이 실제로 만나는 점입니다(3D 뷰어 코어 0.19.0).
   측정 점은 반투명으로 그린 판을 지나 그 뒤 구멍·포켓·홈을 고르므로(3D 뷰어 코어 0.23.0, 포켓·홈은 0.24.0), 판을 숨기지 않아도 판 안 수직·수평 구멍과
   포켓·홈의 벽을 뚫는 점에 붙습니다. 판재 구멍은 위·아래가 막힌 기둥으로 그리므로, 위에서 보면 그 윗면을, 비스듬히 보면 판 너머로 보이는 바깥 벽을 고릅니다.
   포켓·홈은 반투명으로 그리고, 고를 때는 판 면 자리의 뚜껑만 지나고 벽·바닥에서 멈춥니다(3D 뷰어 코어 0.27.0 — 그림·윤곽선은 그대로).
   그래서 판 위에서 포켓·홈의 바닥(위에서 보면 바닥 높이)과 뚜껑 너머로 보이는 안쪽 벽, 포켓 바닥에 뚫은 구멍의 벽을 숨기지 않고 잽니다.
   구멍 그물은 판 면에서 시작하므로 포켓 바닥 구멍을 위에서 가리키면 포켓 윗면 높이의 구멍 윗면(중심 점도 그 높이)을 고르고, 구멍 테두리는 포켓 바닥 높이에 따로 없습니다.
   포켓 위 테두리(윤곽선)는 예전처럼 고르므로 테두리에서 바닥까지 깊이를 잴 수 있습니다.
   뒤에 구멍·포켓·홈이 없는 판 위 자리는 예전과 같습니다.
   공작물 상자와 깎기 시뮬레이션 소재의 면은 그린 면 그대로입니다(시뮬레이션 소재의 벽은 격자 한 칸 너비까지만 압니다).
   찍은 결과는 "끝점 → X축 · 모서리 위"·"끝점 → Z축 · 면 위"처럼 적습니다.
   축이 곡선을 나눈 토막과는 만나지 않고 토막과 곡선 사이만 지나는 자리도 곡선 위 점에 붙습니다(3D 뷰어 코어 0.20.0). 같은 윤곽을 여러 깊이로 깎는 경로에서
   위 점에 머물러 끌어온 Z축이 아래 원호를 뚫는 점, 나선 위쪽 점의 Z축이 아래 바퀴를 뚫는 점, 스플라인 위를 지나는 Z축이 그렇습니다.
   곡선은 짧은 토막으로 그리므로 이런 축은 토막에서 처짐(5°씩 나눈 원호면 반지름의 0.1% 가까이)만큼 떨어져 지나가, 0.19.0까지는 커서에 가까운 축 위 점에만 붙었습니다.
   같은 평면에서 원호 꼭대기를 현과 거의 나란히 스치는 축도 원 위 두 교차에 붙습니다(3D 뷰어 코어 0.22.0·0.23.0).
   크게 당겨 축이 원호를 나눈 꼭짓점을 화면 반 화소 안으로 지날 때도, 실제 교차가 그 꼭짓점에서 떨어져 있으면 끝점보다 원 위 교차가 먼저입니다
   (3D 뷰어 코어 0.33.0). 축과 현의 틈이 붙잡기 거리보다 넓게 보일 만큼 아주 가까이 당겨도 커서가 그 토막의 활꼴 쪽이면 원 위 교차입니다
   (3D 뷰어 코어 0.35.0부터 — 반지름 25 원호를 확대 12단으로 재면 12단 모두, 0.33.0은 11단, 0.32.0까지는 8단, 0.20.0은 한 단도 붙지 않았습니다).
   끌어온 축·끌어온 점의 안내 선이 원호·나선·구멍 테두리·윤곽 호의 꼭짓점을
   스칠 때도 같고, 곧은 경로·모서리의 꼭짓점은 끝점 그대로입니다.
   판 외곽선 둥근 모서리처럼 볼록한 원기둥 벽을 축이 아주 얕게 스쳐, 벽을 나눈 삼각형은 비켜 가고 원기둥만 뚫는 자리도 원기둥 위 점입니다(3D 뷰어 코어 0.22.0).
   이런 축이 삼각형 하나 위에서 원기둥을 두 번 뚫어도 두 교차 모두에 붙습니다(3D 뷰어 코어 0.24.0 — 0.23.0까지는 그 삼각형 가운데 쪽 교차 하나만).
   **잠근 선과 모서리·면이 만나는 점**(3D 뷰어 코어 0.19.0): Shift·화살표·잠금 단추로 방향을 잠근 동안에도 커서 둘레에 점 붙잡기가 없으면,
   잠근 선이 경로·모서리선과 만나는 점("잠근 X축 · 모서리 위")이나 소재 면을 뚫는 점("잠근 Z축 · 면 위")에 붙습니다. 축뿐 아니라 나란한 방향·수직 방향·
   원호 접선으로 잠근 선도 같고("잠근 접선 방향 · 모서리 위"), 원호·나선·스플라인·원기둥 벽과는 실제로 만나는 점입니다(축이 아닌 잠근 선은 3D 뷰어 코어 0.20.0부터 —
   예: 선분 끝에서 Shift로 그 선분 방향에 잠근 선이 원호와 만나는 점, 비스듬히 잠근 선이 판 외곽선 둥근 모서리를 뚫는 점).
   첫 점 축이 원호와 만나는 점을 본 뒤 Shift로 그 축에 잠가도 점이 그 자리에 남습니다. 결과는 "끝점 → 잠근 X축 · 모서리 위"처럼 적습니다.
   잠근 동안 끌어온 점이 있으면 잠근 선이 그 점의 X·Y·Z축과 만나는 점("잠근 X축 · 끌어온 점에서 Y축")에도 붙고, 축으로 잠갔으면 잠근 축 위에서
   끌어온 점과 나란한 자리("잠근 Z축 · 끌어온 점과 나란히")에도 붙습니다(3D 뷰어 코어 0.21.0). 잠근 선 위 점 붙잡기 다음이고 모서리·면보다 먼저입니다.
   예: 구멍 중심을 첫 점으로 찍고 다른 구멍 중심에 머문 뒤 → 키로 X축에 잠그면, 그 구멍의 Y축과 만나는 자리를 바로 찍습니다.
   붙잡을 점 없이 판재의 구멍 벽·원형 포켓 벽·판 외곽선 둥근 모서리 같은 원기둥 벽을 가리켜도 벽을 나눈 삼각형 위가 아니라
   커서 아래 원기둥 위 점을 찍습니다(3D 뷰어 코어 0.21.0 — 판 윗면·곧은 옆면 같은 평면은 그대로).
   휴대폰은 길게 눌러 정밀 조준하는 동안 십자선을 점 위에 잠시 멈추면 같은 식으로 기억합니다(길게 누르기는 정밀 조준이 쓰므로 따로 두지 않았습니다).
   손가락이 떨려 십자선이 멈추지 않으면 조준하는 동안 측정 띠에 나타나는 **끌어온 점 단추**를 다른 손가락으로 눌러 십자선 아래 점을 바로 기억합니다(아래 5).
   둘째 점을 찍거나 측정을 지우면 잊고, Esc는 첫 점을 찍기 전에도 기억한 점부터 지웁니다.
   측정 도구는 파일을 열 때 3D 보기와 함께 받아 두므로 문서가 보이면 바로 켜집니다. 받지 못했으면(연결이 끊김 등) 측정 단추를 누를 때
   다시 받습니다. 받는 동안 단추는 눌린 채 흐리게 보이고 상태 줄에 "측정 도구를 받는 중…"이라 적은 뒤, 받으면 측정을 켭니다.
   받는 동안 단추를 다시 누르거나 Esc를 누르면 켜지 않습니다. 받지 못하면 연결이 끊겼을 때는 연결된 뒤 다시 누르라고,
   연결이 되는데도 못 받으면(앱의 새 버전이 나와 예전 조각이 없음) 새로 고친 뒤 최근 문서에서 다시 열라고 알립니다.
   숨긴 공구, 단면에 잘린 쪽, 재생 중 아직 그리지 않은 이동의 중심에는 붙지 않습니다(중심마다 처음 그린 이동 번호를 차례로 두고 재생 자리를
   코어 붙잡기 한도로 줍니다 — 재생 중에도 중심 목록을 다시 주지 않습니다). 원호 중심이 아주 많아도 코어가 점 범위 나무로 커서 둘레만 보므로
   마우스 이동이 거의 늦어지지 않습니다(중심 10만 개에서 이동 한 번 약 0.2 ms — 모두 훑으면 9 ms).
   읽는 동안 덮개의 **취소**(또는 Esc)로 멈추면 열려 있던 문서를 그대로 둡니다.
   그래픽 문맥을 잃으면(휴대폰에서 앱을 뒤로 보냈다 돌아올 때 등) 되찾을 때까지 3D 보기 가운데에 "그래픽을 다시 준비하는 중…"을 보입니다(3D 뷰어 코어 0.25.0).
   해석이 스스로 정한 것(선반 프로그램으로 읽음 · 소수점 없는 큰 좌표가 많음 · 판별한 방언 Siemens·Haas 등)은 3D 보기 위(좁은 화면은 아래) 띠로 알리고,
   띠의 단추로 바로 바꿔 다시 읽거나(밀링으로 읽기·최소 단위로 읽기) 정보 탭을 엽니다. ✕로 그 문서에서 닫습니다.
   좁은 화면에서는 띠 글을 두 줄까지(띠가 둘 넘거나 재생 띠가 있으면 한 줄) 보이고 글을 누르면 펼치며, 잠깐 뜨는 알림은 아래쪽 띠들 위로 올라가 단추를 가리지 않습니다.
3. 오른쪽 패널(폭 760px 미만이면 아래 시트)
   - G-code·Heidenhain: **코드**(줄을 누르면 그 줄의 이동을 강조, 3D에서 경로를 누르면 그 줄로 이동 — 패널 아래 띠에 그 블록의 상태:
     이동 꼴·F(G93/G95)·S M3/M4·냉각 / 공구·G43 H·G41/G42 D·좌표계·G90/G91·평면·G16·좌표 변환·사이클 / 끝점(고른 점) / 원호 중심·R·방향·각.
     재생 중에는 재생 막대 아래에 재생 중인 이동의 상태) ·
     **공구**(색·지름·Z 최저·시간·이송 길이, 켜고 끄기. 줄을 누르면 그 공구의 첫 이동 줄로, 두 번 누르면 그 공구 경로에 맞춰 보기,
     Z 최저를 누르면 그 공구의 가장 깊은 절삭 줄로, 줄에 마우스를 올리면 X·Y·Z 절삭 범위) ·
     **정보**(방언·단위 바꿔 다시 읽기, Fanuc 선반이면 G 코드 체계 A·B·C, 보기 선택 — **보정 경로 보기**(구간별 반지름·출처, 선반이면 공구 방향과
     **선반 공구 표** — 보정 구간이 쓰는 공구마다 노즈 R(mm)·방향 1~9를 넣으면 파일에 그 값이 없을 때 쓰고 이 브라우저에 기억, 바꾸면 다시 읽음)·**선반 모드**·**회전축 감기**, 이송/급속 길이,
     예상 시간, 범위(급속 포함)와 절삭 범위(이송·호·드릴 — 가장 깊은 Z), 묶음 켜고 끄기, 해석 경고 — 줄 번호를 누르면 그 줄로,
     다시 누르면 같은 경고가 난 다음 줄로, 경고가 난 코드 줄은 줄 번호 앞에 ▲ 표시(마우스를 올리면 경고 글) — 판재 파일(MPR·PGI·XML)도 같음,
     줄 번호·경고 글·횟수를 따로 보여 다른 언어에서도 조각마다 옮겨짐), 3D 보기가 그릴 수 없어 빼거나 기본값으로 바꾼 값이 있으면 **3D 보기 경고**
     (좌표가 수가 아니거나 너무 큰 공구 경로 선분·점·면 꼭짓점, 없는 꼭짓점을 가리키는 삼각형 등 — 코어 장면 알림을 앱 말로, 처음 생기면 한 번 알림),
     **기계·읽기 설정**(앱 전체, 이 브라우저에 기억 — 급속 속도·공구 교환 시간·블록 건너뛰기(/)·H·D 번호 확인·도그레그 급속·
     G54 원점과 G28 기준점의 기계 좌표·축별 허용 범위, 바꾸면 다시 읽음 / 공구를 실제 크기로 표시),
     여러 파일 작업이면 **작업 파일**(주 프로그램 고르기 — 바꾸면 다시 이어 읽음, 파일마다 코드 탭의 시작 줄로 가기, 파일 더하기,
     잇지 않은 파일과 찾지 못한 프로그램)
   - **깎기**(G-code·Heidenhain·판재): 소재 깎기 시뮬레이션을 켜고 끄고(보기 도구 막대 "그리기" 메뉴의 **소재 깎기**, 좁은 화면은 "보기 설정" 메뉴의 같은 항목도 같음),
     공구 경로를 함께 보일지 고릅니다. 켜면 재생 막대의 자리까지 깎은 소재를 그리고(전체 경로면 프로그램 끝까지), 계산 중에는 3D 보기 왼쪽 위에 진행률을 보입니다.
     탭에는 계산 상태, 급속 이동이 소재를 지난 줄(누르면 그 줄로), 소재 상자(X·Y·Z 범위 — 바꾸면 다시 계산, **자동으로**), 해상도(긴 변 칸)·색(깊이로·소재 색),
     공구 표(종류·지름·모서리 R 또는 끝 각, 값의 출처 — 바꾼 값은 공구 번호마다 기억, **기억 지우기**)가 있습니다.
     시뮬레이션할 수 없는 프로그램이면 까닭과 그 줄을 보입니다. 측정 점을 찍고 있어도 소재 그림은 바로 바뀝니다(바뀐 조각 그물만 올림).
     판재 파일은 재생 막대가 없어 기본은 끝까지 깎습니다. **가공 하나씩 따라가기**(처음·이전 가공·다음 가공·끝까지 단추와 막대, ← →)로
     가공 목록 차례대로 k개까지만 깎아 보고, 지금 가공을 가공 그림·가공 탭·상태 막대에서 강조합니다("가공 3 / 5개까지 깎았습니다").
     끝까지 보고 있을 때 다음 가공은 첫 가공부터 갑니다. 패널을 닫으면 3D 보기 아래에 같은 단추의 띠가 남습니다(✕ = 끝까지, 측정 중에는 숨김).
     **가공 그림도 보이기**로 해석한 구멍·홈·포켓·윤곽 그림을 함께 그릴지 고릅니다. 시뮬레이션하지 않은 가공
     (옆면·아랫면·엣지 밴딩 등)을 까닭별로 보이고, 공구 표는 구멍 지름·공구 번호·경로 폭별입니다(바꾼 값은 판재 공구끼리 따로 기억)
   - MPR·PGI·XML: **가공**(작업 목록) · **변수** · **코드** · **정보**(꺼진 가공이 있으면 **꺼진 가공도 그리기**) · **깎기**.
     3D에서 구멍·포켓·홈을 누르면 목록에서 고른 것처럼 그 가공을 고릅니다. 반투명 판 너머로 보이는 구멍·포켓·홈도 판을 숨기지 않고 누르면 되고,
     포켓 바닥에 뚫은 구멍을 위에서 누르면 그 구멍을 고릅니다(측정처럼 포켓·홈 뚜껑을 지납니다).
     뒤에 가공이 없는 판 위를 누르면 판을 고릅니다. 깎기 시뮬레이션 중에는 예전처럼 가장 앞에 그린 것을 고릅니다
   - 재생 막대: 처음·이전 이동·재생/멈춤·다음 이동·전체·여기까지 그리기(고른 줄의 마지막 이동까지), ×1·×10·×100·×1000, 시간 막대 —
     지나간 경로만 진하게 그리고 공구 위치를 표시합니다(모양은 공구 이름 — 볼·드릴·엔드밀, 설정에 따라 실제 지름 크기). 한 이동씩 걸으면 시간이 0인 이동도 하나씩 가고 코드 보기가 따라갑니다.
   - 코드 위 찾기 칸(Ctrl/⌘+F): 글(대소문자 무시)·N 번호(N100은 N1000과 구별)·":120"(120번 줄로 가기), Enter 다음·Shift+Enter 이전,
     찾은 줄은 줄 앞에 표시. 가상 목록이라 브라우저 찾기 대신 이 칸을 씁니다.
4. 아래 상태 막대에 형식·단위·파일 크기·이동/선분 수·읽은 시간, 해석 경고 수(누르면 정보 탭)와 고른 것(줄·이동·측정 거리와 붙잡은 점의 종류, 측정 중 방향 잠금 안내)이 보입니다.
5. 휴대폰·터치: 폭 760px 미만이거나 휴대폰 가로 화면(손가락 기기에 높이 500px 미만)에서는 도구 막대를 한 줄(전체 보기·표준 뷰·보기 설정·단면·측정·재생·패널)로 줄이고,
   뷰 큐브를 작게, 패널은 처음엔 닫아 둡니다. 손가락으로 뷰 큐브를 누르면 큐브를 크게 펴고(표준 뷰에서 누를 자리가 모두 24 CSS px 이상 — 비스듬히 돌린 뷰는 더 좁을 수 있음), 편 큐브를 다시 눌러 뷰를 고릅니다
   (코어 0.44.0 — 마우스·펜은 바로 고름, 큐브 밖·3D 보기·Esc는 접음).
   원근/평행·그리기 모드·격자·뷰 큐브·좌표축·PNG 저장은 "보기 설정" 메뉴로 모읍니다.
   뷰 큐브·키 F·1~7·전체 보기·고른 것 맞춰 보기의 카메라 움직임은 기기의 움직임 줄이기 설정(prefers-reduced-motion)을 따르고, 앱을 연 뒤 설정을 바꿔도 새로 고침 없이 따릅니다.
   패널(시트)을 닫은 채 재생하거나 재생 자리가 있으면 3D 보기 아래에 재생 띠: 시간·줄·이동 상태(이송·주축·공구·모달 G),
   처음·이전 이동·재생/멈춤·다음 이동·속도·✕(재생 끝내기 — 전체 경로)와 시간 막대(측정 중에는 숨김, 넓은 화면도 패널을 닫으면 같음).
   판재 깎기에서 가공 하나씩 따라가는 중이면 같은 자리에 지금 가공과 처음·이전 가공·다음 가공·✕(끝까지), 막대를 둔 띠가 보입니다(단추 38px).
   좁은 화면이나 손가락 기기에서 측정을 켜면 3D 보기 아래 가운데 띠에 다음에 누를 곳, 거리와 dx·dy·dz, 붙잡은 점의 종류를 크게 보이고,
   "다시 재기"(찍은 점과 결과 지우기)와 ✕(측정 끝내기) 단추를 둡니다(Esc 대신, 시트 패널을 열지 않아도 됩니다).
   첫 점을 찍은 뒤에는 측정 띠에 **잠금 단추**가 생깁니다: 정밀 조준으로 축·나란한 방향(첫 점이 경로 끝이면 그 경로의 다른 끝도,
   원호·스플라인의 끝·가운데 점이나 그 위의 점이면 그 곡선 위 — 접선 방향)에 맞춘 채
   다른 손가락으로 누르면 그 방향을 잠그고(다시 누르면 풀기), 맞춘 방향이 없으면 띠 위에 맞추는 법을 알립니다(잠금이 걸리면 그 알림은 거둡니다).
   정밀 조준하는 동안에는 측정 띠에 **끌어온 점 단추**(작은 +와 축 점선 그림)가 잠금 단추 옆에 나타납니다. 조준하는 손가락을 둔 채 다른 손가락
   (한 손으로 들고 있으면 그 손 엄지 — 띠는 화면 아래 가운데)으로 누르면 십자선 아래 붙잡은 점(끝점·가운데 점·중심·교차점·수직 발 등)을 끌어온 점으로
   기억합니다. 십자선을 0.5초 멈추지 않아도 그 점의 X·Y·Z축에 붙습니다(3D 뷰어 코어 `setMeasureTrackPoints` — 최근 셋까지, 첫 점 전에도).
   단추에 기억한 점 수를 적고, 기억한 점이 있는 동안은 조준하지 않아도 단추가 남습니다. 붙잡은 점이 없으면(축 위·빈 곳) 띠 위에 맞추는 법을 알리고,
   기억한 점은 "다시 재기"로 지웁니다. 조준하지 않을 때는 단추가 없어 측정 띠가 예전과 같고, 넓은 화면(마우스)은 측정 띠가 없어 머무르기만 씁니다.
   측정 중 한 손가락을 거의 움직이지 않고(10화소 안) 길게(0.35초) 누르면 손가락 위 64px에 십자선이 떠 정밀 조준합니다 — 끌면 십자선이 따라가고
   (붙잡을 점·거리를 미리 보입니다) 떼면 그 자리를 누른 것으로 칩니다. 십자선 자리는 보통 터치 누르기(14화소)가 아니라
   마우스와 같은 좁은 허용 거리(선분 6화소, 끝점 10화소 — 코어에 펜 포인터로 알림)로 골라, 구멍·선분이 빽빽한 곳에서도 미리 본 점이 그대로 찍힙니다.
   조준하는 동안 거리 글상자는 십자선과 손가락, 첫 점과 십자선 아래 점의 표식을 비켜 그려, 첫 점 가까이를 가리켜도 거리와 점이 가려지지 않습니다.
   휴대폰에서는 거리 글상자가 화면 폭의 절반을 넘어, 두 점이 오른쪽 위면 뷰 큐브 밑에, 아래쪽이면 측정 띠 밑에 그려졌습니다. 지금은 둘을 비켜 그립니다.
   둘째 손가락이 닿으면 조준을 그만두고 두 손가락 이동·확대로 넘어갑니다.
   손가락 기기의 안내에는 키(Esc) 설명 대신 길게 누르기를 적고, 파일 고르기 상자는 확장자로 거르지 않습니다
   (iOS에서 .nc·.mpr 등이 흐리게 막히지 않게 — 모르는 확장자는 앞부분을 보고 이진 파일을 바로 막고, 글 파일은 내용으로 형식을 가립니다).
6. 최근 문서: 파일 고르기·끌어다 놓기(홈 화면 앱의 공유 받기·연결 프로그램 포함)로 열린 파일은 이 브라우저의 IndexedDB(`opencad-nc`)에 새것부터 8개까지 두고
   (60MB 넘는 파일, 예제, `?open=`으로 받은 파일은 두지 않음), 시작 화면의 **최근 문서**에서 이름·크기·연 시각을 보고 눌러 다시 엽니다.
   휴대폰 브라우저가 뒤로 간 탭을 버렸다가 다시 읽어도 파일 앱을 다시 거치지 않습니다. 여러 파일 작업은 이은 글 하나를 주 프로그램 이름으로 두고
   ("파일 N개 작업"), 다시 열면 같은 작업으로 읽습니다. 줄마다 ✕(그 항목만 지우기)와 **모두 지우기**가 있고,
   서버로는 보내지 않습니다(비공개 창처럼 저장소를 못 쓰면 목록이 생기지 않습니다). 읽는 동안 덮개(취소 가능)를 보이고,
   저장된 내용이 없으면 그 항목을 지우되 잠깐 못 읽었으면(연결 끊김 등) 항목을 두고 다시 눌러 보라고 알립니다.
   iOS에서 홈 화면에 추가한 앱은 Safari와 저장 공간이 따로라, Safari에서 연 최근 문서는 홈 화면 앱에 보이지 않습니다(반대도 같음).
7. 홈 화면에 추가: 웹 앱 매니페스트(원본 `site/manifest.webmanifest` — 이름 "OpenCAD NC 뷰어", 짧은 이름 "NC 뷰어", `standalone`)와
   192·512·maskable 512 아이콘, iOS용 180px `apple-touch-icon.png`로 휴대폰 홈 화면에서 주소 막대 없이 앱처럼 엽니다.
   빌드가 `manifest.webmanifest`와, 번역해 만든 `<언어>/manifest.webmanifest`(그 언어 페이지에서 시작)를 씁니다.
   홈 화면 앱에서는 제목 막대를 상태 막대(노치) 아래로 내리고,
   제목·상태 막대를 아래로 당겨도 페이지를 새로 읽지 않습니다(`overscroll-behavior-y: none` — 코드 목록·패널·시작 화면은 그대로 굴러갑니다).
8. **오프라인**: 빌드가 만든 서비스 워커(`dist/sw.js` — 본문 `tools/sw-source.mjs`, 목록·판 이름은 공용 사이트 도구)가 앱 껍데기(언어 페이지·앱 정보·아이콘)와 빌드 결과(해석 워커·번역 사전, 문서를 열 때 받는 3D 보기·측정 도구·정보 탭 조각과 예제 조각 포함)를
   미리 담아, 신호 없는 현장에서도 한 번 열어 본 기기라면 앱이 열리고 최근 문서를 엽니다. HTML은 네트워크 먼저(배포가 바로 보이게, 안 되면 담아 둔 것),
   미리 담은 파일과 빌드 결과(`assets/`)는 담아 둔 것 먼저이고, 그 밖(`?open=`으로 받는 NC 파일 등)과 앱 범위 밖 주소는 서비스 워커가 손대지 않습니다
   (바뀐 파일이 옛것으로 열리거나 큰 파일이 쌓이지 않게). 새 판이 설치되면 "새 버전이 있습니다 · 새로 고침" 알림을 띄우고,
   누르면 새 판으로 바꿔 한 번 다시 읽습니다(판 이름은 담는 파일들의 내용 지문).
   **공유 받기(Android)**: 앱 정보의 `share_target`(POST `…/share-target`)으로 메일·메신저·파일 앱의 "공유 → NC 뷰어"를 받습니다.
   파일 하나(60MB 이하)는 서비스 워커가 최근 문서(IndexedDB)에 넣고 그 언어 페이지의 `?recent=<id>`로 엽니다.
   여러 파일(주 프로그램과 부프로그램)이나 60MB 넘는 파일은 같은 저장소의 한 번 쓸 자리에 두고 `?share=<열쇠>`로 열어,
   앱이 읽자마자 지우고 여러 파일은 한 작업으로 이어 읽습니다(이은 작업은 파일을 고른 것처럼 최근 문서에 남음). 받지 못하면 까닭을 알립니다.
   **데스크톱 파일 열기**: `file_handlers`(뷰어가 여는 확장자 전부 — `NC_EXTENSIONS`에서 빌드 때 만듦)와 `launchQueue`로 설치한 앱을
   파일 탐색기의 "연결 프로그램"으로 쓸 수 있고, 여러 파일을 함께 고르면 창 하나에서 한 작업으로 엽니다(`launch_type: single-client`,
   이미 열린 창이 있으면 그 창으로). 앱 정보에는 `id`를 두지 않습니다(언어 페이지마다 start_url이 id). 개발 서버는 서비스 워커를 등록하지 않습니다.

**3D 보기 키보드 붙잡기·고르기**(56차 — 3D 뷰어 코어 0.46.0·0.47.0): 마우스 없이 3D 보기에서 고르고 잽니다. 3D 보기(캔버스)에 초점을 두고 Enter를 누르면
가상 커서가 가운데에 켜지고, 화살표로 옮기며 Tab으로 그 자리의 후보를 돌리고 Enter로 고르거나 측정 점을 찍습니다. 측정 모드에서는 마우스 미리 보기와 같은 규칙의
붙잡을 점(끝점·가운데 점·중심·교차점·축 등)을, 고르기에서는 누르기와 같은 선택(판재는 반투명 판 너머)으로 커서 자리에 겹친 것을 앞에서부터 돌립니다.
고르기 후보는 앱 단위로 묶습니다 — 공구 경로는 코드 줄(원호를 나눈 선분·고정 사이클의 이동이 한 줄), 판재는 가공(구멍 중심 점과 그 그물) — Tab은 같은 줄·가공의 다른 선분을
건너뛰어 다음 줄·가공으로 가고, Enter는 그 줄·가공을 고릅니다(코드 목록·가공 목록에서 고른 것과 같습니다). 후보는 줄·가공 16개까지라 한 줄의 원호 선분이 커서 둘레에
아주 촘촘히 겹쳐도 그 뒤의 줄·가공이 목록에 듭니다(58차). 커서가 꺼져 있으면 화살표는 위 표의 앱 키이고(재생 걸음·
한 가공씩·줄 이동·측정 방향 잠금), 앱이 쓰지 않는 화살표도 커서를 켜지 않아 켜는 키는 Enter뿐입니다. 측정 첫 점 뒤 방향 잠금은 커서가 켜진 동안 Shift(지금 방향)로 합니다.
그동안 상태 줄·측정 띠의 잠금 안내는 화살표 안내("화살표로 방향 잠금")를 내지 않고 커서 아래에 Shift로 잠글 방향이 있을 때 그 안내만 내며, 붙잡기 툴팁과 함께
가상 커서를 켜고 옮기고 끌 때마다 맞춥니다(57차 — 포인터 이동이 없어도). 시작 화면의 키 안내 줄에도 Enter(가상 커서)가 있습니다(57차).
커서를 켜고 옮기고 돌리고 찍을 때마다 화면 읽기 프로그램이 읽는 알림(aria-live)을 화면 언어로 냅니다(예: "가상 커서를 켰습니다. 줄 4 · 직선 이송 · F300: X 20, Y 15, Z 0.
옮기기 ←→↑↓ · 후보 Tab · 고르기 Enter · 끄기 Esc", "첫 점을 찍었습니다. 가운데 점: X …, Y …, Z …" — 측정 수는 측정 거리 글상자와 같은 자릿수).
3D 보기 캔버스는 이 키를 설명(aria-description)으로 알립니다.

주소 인자: `?sample`(예제 바로 열기), `?open=<같은 출처 주소>`(그 파일을 받아 열기 — 자동 확인용, 다른 사이트 주소는 열지 않음).
공유 받기가 붙이는 `?recent=<id>`·`?share=<열쇠>`·`?share-error=<까닭>`은 한 번만 쓰고 주소에서 지웁니다.
테마는 시스템 설정을 따르고, 제목 막대 단추로 고른 테마는 이 브라우저에 기억합니다.
자동 확인용으로 `window.opencadApp`(상태 `state`, `open`·`openSample`·`openUrl`·`reparse`·`cancel`·`setSection` 등)을 둡니다.

## 라이브러리로 쓰는 법

```ts
import { loadNcFile } from 'opencad-nc';

const { parsed, scene } = loadNcFile('part.nc', bytes); // 형식은 앞부분·확장자로 자동 판별
// parsed.kind: 'gcode' | 'heidenhain' | 'mpr' | 'pgi' | 'xml' (판재 형식은 parsed.part: MprPart)
// scene: Scene3d (opencad-viewer3d의 Viewer3d.setScene에 넘긴다)
```

형식별 함수(`parseGcode`, `parseHeidenhain`, `parseMpr`, `parsePgi`, `parseKdtXml`, `ncToScene`, `mprToScene`)와 확장자 목록(`NC_EXTENSIONS` 등), `isPanelKind`도 `src/index.ts`에서 내보냅니다.

선택 기능(기본은 모두 꺼짐 — 켜지 않으면 결과가 예전과 같습니다):

```ts
// 선반 모드('auto'면 글로 판별 — Fanuc 선반 G 코드 체계 latheSystem: 'A'|'B'|'C'도 고르지 않으면 판별, p.latheSystem),
// 회전축 감기, 반경 보정용 공구 표(키 = D 번호, LinuxCNC는 공구 번호)
const p = parseGcode(text, { lathe: true, rotary: { A: 'x', stepDeg: 2 }, toolTable: { 1: { diameter: 10 } } });
p.compRuns; // 보정 구간 [{ first, end, side, plane, radius, source, line }]
const scene = ncToScene(p, { compPath: true }); // 선분 묶음 'nc-comp'(묶음 '보정 경로'), meta.compRuns
const cp = ncCompPath(p, { radius: 5 }); // 조각(직선·호) 구조 배열 — compPathSegments(cp)로 선분
// 선반 공구 끝 R 보정: 노즈 반지름과 LinuxCNC 공구 방향(1~8이면 가상 공구 끝 경로, 9는 노즈 중심)
const t = parseGcode(text, { lathe: true, toolTable: { 1: { radius: 0.4, orientation: 3 } } }); // 또는 machine.latheToolsMm(mm, 파일에 없을 때만)
t.compRuns; // [{ …, radius: 0.4, tool: 1, orientation: 3, orientationSource: '공구 표 T1' }]
```

판재 장면(`mprToScene`)의 `meta.lids`는 포켓·홈 그물 id마다 뚜껑(들어가는 판 면 자리의 끝면) 삼각형 구간 `{ start, count }`입니다.
3D 뷰어 코어 `setItemPickThrough(id, [lid])`에 넘기면 반투명 판 너머 고르기가 뚜껑을 지나 포켓 바닥·벽에서 멈춥니다(뷰어 앱이 그렇게 씁니다).

3D 뷰어 코어는 0.68.0(커밋 `0f5e421` — 태그 없음)을 `github:GyuTae-Kim/opencad-viewer3d#0f5e42176c2a04bca8d2830b2cd9671a5db5d383`(전체 SHA)로 받습니다(0.38.0~0.68.0을 쓰는 길은 아래 0.37.0 문단 다음). 보기에서 누르기는 0.26.0 `onPick`의 `front`로
판 너머 고르기와 가장 앞 고르기를 알림 하나에서 받고, 판재 포켓·홈 뚜껑은 0.27.0 `setItemPickThrough`로 판 너머 고르기에서 지나가게 합니다.
끌어온 점에서 나란함·수직은 0.28.0 `inference.trackDirs`의 `edge` 거르기(`src/app/refine.ts`의 `trackDirEdge` — 이동 번호·판재 붙잡기 표로 곡선을 나눈 현을 가름)로 켜고,
그 선이 만나는 점은 0.29.0 `meets`로 켭니다(곡선·원기둥과 만나는 점은 이미 쓰던 `refine`의 `'axisEdge'`·`refineFace`의 `'axisFace'`가 축 이름 없는 안내 선으로 다듬음).
첫 점 나란함의 기준도 0.29.0 `inference.parallelEdge`에 같은 `trackDirEdge` 함수를 줘 거릅니다(같은 함수라 코어가 같은 선분을 한 번만 물음).
`trackDirEdge`는 곡선을 G1으로 풀어 쓴 곡선 조각도 받지 않습니다(`src/app/g1curve.ts` — 측정 도구 조각, 처음 물을 때 이동 표마다 한 번 셈해 이동 20만 개에 약 27 ms).
판정 규칙은 이렇습니다. 같은 선분 묶음의 이웃 곧은 토막(이송·급속) 사이 꺾임이 0.1°~20°이고 두 토막 길이 비가 2 이하면 굽은 마디, 이웃한 굽은 마디는
꺾는 쪽이 45° 안으로 같고 꺾임 비가 1.8 이하면 이어 한 구간으로 봅니다. 구간 첫·끝 마디가 안쪽 마디(넷까지) 평균의 1/1.4보다 덜 꺾이면 빼고(곡선에 접선으로
들어오고 나가는 직선은 남김), 남은 굽은 마디가 셋 이상이고 꼭짓점이 구간 처음·끝을 잇는 직선에서 0.005(문서 단위)보다 멀면 그 구간 토막은 모두 곡선 조각입니다.
합성 프로그램 308개(원·나선·타원을 G1으로 나눈 것, 진짜 직선을 섞은 것 — 소수 셋째 자리로 반올림)에서 곡선 토막 31,520개 가운데 31,349개를 곡선 조각으로 가렸고

판재에서는 안내 선이 원기둥 벽(구멍·둥근 포켓 벽, 판 외곽선 둥근 모서리) 곡면만 뚫는 면의 열린 교차를 0.32.0 `meets`의 `openFaces: true`로 켭니다

`refineAxisEdge`가 고른 근이 묻는 토막 범위 밖이면(코어가 받지 않는다) 토막 가운데에 가까운 근으로 다시 풉니다(36차 — 그 전에는 커서 쪽 토막의 교차를 반쯤 놓쳤고,

0.33.0의 바뀐 기본 동작(원근으로 아주 가까이 확대해 꼭짓점이 눈 뒤로 넘어간 벽 칸도 면의 열린 교차 후보로 모음)은 `refineFace`를 주는 판재에만 닿습니다.

선이 구멍 벽 칸을 얕게 뚫는 코어 교차(현 위 "면 위") 둘레와 누운 작은 구멍 옆면의 긴 칸을 따라가는 안내 선이 원기둥 위 다듬은 교차에 붙습니다.

**실제 파일 훑기**: 각자 가진 NC 파일 폴더를 앱 워커와 같은 해석 길로 읽어 예외·경고·빈 경로·시간을 모읍니다(파일을 바꾸거나 저장소에 넣지 않습니다).

```bash
npm run sweep -- --dirs "<폴더1>:<폴더2>" --out .runtime/sweep/before   # 또는 OPENCAD_SWEEP_DIRS="<폴더1>:<폴더2>"
#   --jobs 4(자식 프로세스 넷으로 나눠 해석) --limit 100(앞의 100개만) --force(같은 --out 덮어쓰기)
npm run sweep:compare -- .runtime/sweep/before .runtime/sweep/after --fail-on-change
```

폴더를 주지 않으면 쓰는 법만 찍고 끝납니다(CI에서는 돌지 않습니다). 앱이 여는 확장자만 고르고, 내용(sha256)이 같은 파일은 한 번만 읽으며
C 머리 파일(.h)은 뺍니다. `<out>/records.jsonl`에 파일마다 분류(ok·warn·empty·error)·형식·방언·지표(선분·이동·가공 수, 장면 서명 등)·경고 코드를,
`summary.json`에 분류·형식별 개수, 예외·경고 코드별 개수, 해석 시간 백분위, 품질 지표를 씁니다. 경로는 이 로컬 결과에만 남기고 보고·저장소에는 옮기지 않습니다.
`sweep:compare`는 같은 내용 해시끼리 분류·지표가 바뀐 파일과 새 예외를 보이고, `--fail-on-change`면 바뀐 것이 있을 때 1로 끝납니다.

## 검색·공유 메타데이터와 콘텐츠 수정일

`site/metadata.json`을 공통 원본으로 삼아 공용 사이트 도구의 Vite 플러그인이 제목·설명·canonical·Open Graph·Twitter Card·JSON-LD를 초기 HTML에 넣습니다. 같은 원본으로 앱의 공개 주소를 담은 `sitemap.xml`도 생성합니다. 공유 이미지는 각 앱의 `public/og-opencad.jpg`이며 앱 파일과 함께 배포합니다. `robots.txt`는 같은 호스트 루트(`https://gyutae-kim.github.io/robots.txt`)의 설정이 적용됩니다.

`site/content-history.json`에는 실제 콘텐츠 수정 시각과 지문을 저장합니다. 초기 HTML 본문·메타데이터·공유 이미지와 빌드된 앱/워커 JavaScript·CSS를 비교하므로 앱 기능이 바뀌면 날짜 갱신이 필요합니다. 수정일 자체와 소스 맵은 비교에서 제외합니다.

1. 콘텐츠를 변경한 실제 UTC 시각을 기록하고 `npm run update:content-dates -- --at YYYY-MM-DDTHH:mm:ssZ`를 실행합니다.
2. `npm run build`로 다시 빌드합니다. 변경되지 않은 콘텐츠는 기존 날짜를 유지하며, 날짜가 오래되었거나 잘못된 경우 SEO 검사가 실패해 배포를 막습니다.
3. `npm run test:seo`와 기존 테스트를 실행하고 메타데이터·수정일 기록을 함께 커밋합니다.

일반 빌드나 배포 시각으로 날짜를 자동 갱신하지 않습니다. `sitemap.xml`의 `lastmod`와 앱 구조화 데이터의 `dateModified`는 동일한 기록을 사용합니다. 배포 뒤에는 앱·사이트맵·공유 이미지의 실제 공개 응답을 확인하고, 포트폴리오 통합 사이트맵의 연결 날짜도 새 앱 사이트맵과 맞춥니다. 사이트맵 게시와 검색엔진의 실제 수집·색인 완료는 별도로 확인합니다.


## 다국어 UI와 정적 소개

한국어 기본 주소와 영어(`/en/`), 일본어(`/ja/`), 중국어 간체(`/zh-CN/`), 독일어(`/de/`) 페이지를 제공합니다. 각 언어의 소개 본문과 검색·공유 메타데이터를 빌드할 때 생성하며, `hreflang`과 사이트맵이 같은 페이지의 언어들을 연결합니다. `site/locales/*.json`에 한국어 원문과 번역을 저장하고, 브라우저는 선택한 언어의 사전만 내려받습니다. 방문 중 외부 번역 서비스는 호출하지 않습니다.

우측 상단 지구본 아이콘에서 언어를 선택합니다. 방향키로 이동하고 Escape나 바깥 클릭으로 닫을 수 있습니다. 언어 선택은 URL에 반영하며, 열린 문서나 편집 상태를 다시 만들지 않고 화면 문구·접근성 설명·오류·도움말을 갱신합니다. 명령 식별자·입력값·파일명·모델 이름·원본 도면의 문자는 번역하지 않습니다. 새 데이터 이름을 표시하는 요소에는 `translate="no"`를 지정하고, UI 문구의 `{0}` 같은 변수 자리를 변경하지 마세요. 여러 줄 메시지와 새 한국어 문구도 번역 사전에 추가해야 합니다. 묶음 이름(급속 이송·구멍·공구 없음·가공 종류 등)은 앱 낱말이라 옮기고, 이름 붙은 공구의 묶음·변수 표의 이름·식·설명은 파일 자료라 그대로 둡니다. 코드 목록은 글을 옮기지 않지만 목록 이름과 경고 줄 번호 칸의 풍선 글(경고가 둘 넘으면 줄마다)은 옮깁니다. ` · `로 이은 문장은 짧은 변수 문구(예: `줄 {0}`)가 뒤 조각까지 그대로 잡으면 조각마다 따로 옮깁니다(남는 한국어가 적은 쪽을 고름 — 잡은 파일·공구 이름은 여전히 그대로).
변수 자리가 잡은 값은 옮기지 않으므로, 해석기가 이유 글을 끼우는 경고(예: Heidenhain FK의 "…을 정할 자료가 모자람 — 다음 블록 자료가 필요한 FK는 그리지 않음",
MPR 윤곽 모서리 둥글리기·모따기)와 정보 탭 목록에 글 하나로 들어가는 보정 경로 경고("보정 경로: N번 줄: …")는 이유마다 전체 꼴을 사전에 둡니다
(`tests/warn-i18n.test.ts`가 네 언어에서 한국어가 남지 않는지 봅니다).
그릴 것이 없는 프로그램을 열 때의 알림은 안내 글·"해석 경고"·줄·첫 경고 글을 글 마디마다 나눠 두어, 첫 경고도 정보 탭 경고 목록과 같은 열쇠로 옮깁니다.

번역층은 사전 열쇠와 같은 글 마디를 통째로 바꾸고 다른 언어 사전의 번역 글도 원문으로 되찾으므로, 파일에서 온 글(주석·줄 원문·이름 붙은 공구·프로그램·작업 파일·
MPR 가공 이름)을 앱 글에 그대로 이어 붙이면 이름이 바뀔 수 있습니다(54차에 고침 — 예: 공구 "무늬 · 연구"가 "Texture · 연구"로). 파일 글만 담는 칸에는
`translate="no"`를 두고, 앱 글과 섞이는 곳(상태 줄 고른 것, 재생 막대·띠의 줄과 상태, 아래 띠, 안내 띠, 알림)은 `src/app/filetext.ts`의 `mix`·`fileText`로
지은 뒤 `mixNodes`·`mixText`(`src/app/i18n.ts`)로 옮깁니다 — 파일 글 자리를 사용 영역 글자로 비워 둔 채 옮기고 되돌리며, 그렇게 넣은 요소는
`data-i18n-skip`(속성은 `data-i18n-keep`)으로 번역층에서 빼고 언어를 바꾸면 앱이 다시 그립니다. 파일 글은 모두 글 마디로만 넣습니다(HTML로 넣는 곳 없음).

`npm run test:i18n`은 언어 전환과 문서 데이터 보존을, `npm run check:i18n`은 다섯 언어의 정적 소개·canonical·언어 링크·사전 변수·에셋 경로를 검사합니다. 번역이나 앱을 수정하면 기존 콘텐츠 수정일 갱신 절차를 따른 뒤 다시 빌드합니다. 자동 번역 초안의 주요 메뉴와 제품명은 교정했으며, 긴 기술 설명에는 추가 원어민 감수가 필요합니다.
52차에 사전 전체(열쇠 1,375개 × 네 언어)를 읽어, 한국어 낱말을 다른 뜻으로 옮긴 것(고름 → 고름(膿), 무늬 → 패턴, 표지 → 책 표지, 열 파일 → 열(列) 파일,
감지 않음 → 감지(檢知), 멈춤 → 갇힘 등), 서술 경고를 1인칭·명령형으로 옮긴 것, 코드 낱말(THEN·WHILE·TOOL CALL·STEP 등)을 옮긴 것, 깨진 글을 고치고
같은 개념은 한 말로 맞췄습니다(단면 Section·Schnitt·剖面, NC 블록 程序段·Satz, 공구 끝점 제어 tool center point control). `tests/i18n.test.ts`가
이 앱 문맥의 금지 낱말 짝·1인칭과 명령형 경고·코드 낱말 보존을 네 언어에서 봅니다.
